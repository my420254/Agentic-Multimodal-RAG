# PRD v3（收敛版）：证据驱动型校园求职 Agent

> 状态：**v3 为唯一实施基准**，v1/v2.0 归档为"演进过程"材料（答辩时可讲"我做过范围裁剪"，但不再按 v2 开工）。
> 一句话变更：**保留 v2 的差异化论点，砍掉 v2 的基础设施。**

---

## 1. 对 v2.0 的裁决（每一行都有理由，答辩可复用）

| v2.0 的内容 | 裁决 | 理由（面试官会问的那一句） |
| :--- | :--- | :--- |
| 事实保真护栏（无实测数据强制占位符） | **保留，升为第一卖点** | 这是通用模型结构上不做的事，且 8 类对抗样本可回归 |
| 4 阶自适应追问 + PIVOT_FALLBACK | **保留，升为第二卖点** | 可现场演示"我说不会 → 它降维并记录盲区" |
| 证据锚点（page + bbox，点击回溯） | **保留，升为第三卖点** | 现场点引用跳原文，一秒说服 |
| 多租户隔离 + JWT + owner_id 强制过滤 | **保留（P0）** | 唯一不能省的安全底线，且可自动化验证 |
| 三层记忆 L1/L2/L3 | **保留，但砍掉"离线 Dream"** | 价值在写入/冲突/遗忘策略，不在 Kafka 异步 |
| 离线 Golden 评测集 | **保留并加强（最该投入）** | 这是你唯一能"证明"的东西 |
| Go (Gin) 网关 | **砍掉** | 只做鉴权+限流的 Go 网关 = 反向代理；"为什么不用 Nginx/Kong"无法回答。若写成有业务逻辑的服务，4 周不够 |
| Kafka 多 Topic 事件总线 | **砍掉**（降级为 Redis 队列 / Celery） | 校园日活几十人，峰值 5 QPS；用 Kafka 会被追问"峰值多少" |
| 1000+ QPS / P99 < 30ms | **砍掉** | 业务上不存在；且只能压到网关，压不到 LLM 链路，一问就穿 |
| 完整 Tool Registry + 三态熔断 + 全链路 Trace | **降级**：工具表 + 调用日志 + 超时 | 概念留，体系砍。日志能证明的事不需要框架 |
| "生产级 Agent Harness 运行时" 定位 | **改掉** | 定位越大，被追问的边界越多；学生项目讲"我解决了三个具体问题"更稳 |

**裁决依据只有一条**：这个组件能否在答辩里回答"不做它会怎样 / 更简单的替代是什么 / 数字哪来的"。答不上来就是负债。

## 2. v3 定位

> **面向高校学生的证据驱动型求职 Agent：让每一条建议可回溯，让每一个分数有证据，让每一次面试可复现。**
> 三个可演示能力：**不编数字 / 会降维追问 / 能点回原文**。

技术栈（与现有仓库一致，不重写）：

```
React (Vite) ──SSE──> FastAPI（鉴权 / 状态机 / RAG / 报告）
                        ├── PostgreSQL 或 SQLite（业务数据 + 画像 + 报告）
                        ├── Redis（L1 会话 / 限流 / 锁）
                        ├── Celery 或 Redis 队列（解析、报告生成）
                        └── 模型层（LLM / VLM / Embedding / Rerank，可切本地）
```

- 不引入第二语言运行时；不引入 Kafka；不引入 K8s。
- 向量库：沿用现有 Chroma 或迁 pgvector（二选一，**先不迁**，迁移是纯风险零收益）。

## 4. 关键设计（只写与验收强相关的部分）

### 4.1 隔离

- `user_id` 只从 JWT 取；仓储层统一 `WHERE owner_id = ?`；路由层禁止裸查询。
- 向量检索强制带 `owner_id` 过滤（metadata filter）；Redis key `u:{uid}:...`。
- 删号：事务内级联删除 + 文件 + 向量 + Redis，60s 内生效，脚本可验证。

### 4.2 引用

- Chunk 元数据：`{doc_id, doc_name, doc_type, page, bbox, section_name, version}`。
- 回答必须至少 1 条引用；不足则输出"以下为通用建议，未引用你的材料"。
- 前端：点击引用 → 抽屉打开原文件 → 高亮 bbox。

### 4.3 事实保真

- 无实测数据的改写 → 强制占位符 `[请补充真实压测指标]`。
- 检测：数值型断言（QPS / 百分比 / 倍数）若在原文中不存在 → 拦截并改写。
- 回归：`data/benchmark_resumes/` 8 份样本 + 注入样本，断言"虚构数值 0 例"。

### 4.4 面试状态机

- 阶段：动机 → 原理 → 边界 → 量化 → 收敛；`DEEP_PROBE / PIVOT_FALLBACK / WRAPUP` 三动作。
- 人设：`strict_architect / gentle_mentor / business_tl`（三维参数：严格度、深度、发散度）。
- 发散度：0 = 100% 材料内；1 = ≥70% 材料内；2 = 延伸题 ≤30% 且必须标注。**可统计、可验收**。
- 学生答"不会" → 降维 + 记盲区（写入 L2/L3），**成功率可测**。

### 4.5 评分

- 五维：事实一致性 / 技术深度 / 结构化表达 / 量化证据 / 沟通抗压，各 1–5 锚点。
- 每维附 ≥1 条学生原话证据；temperature ≤ 0.3；同转录 3 次 ICC ≥ 0.70。

## 5. 验收准则（28 条，全部可自动化或可人工量化）

### A. 隔离与安全（4 条，硬门槛）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| A1 | 无 token/过期 token 访问业务接口 100% 401 | pytest 全路由参数化 |
| A2 | 代码中 `grep -r "default_user\|default_student"` 结果为 0 | CI 断言 |
| A3 | 30 条跨用户用例（材料/切片/会话/报告/画像/记忆）100% 拒绝 | 越权测试套件 |
| A4 | 删号后 60s 内 DB/文件/向量/Redis 残留为 0 | 清理扫描脚本 |

### B. 事实保真（3 条，核心差异化）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| B1 | 缺乏量化数据的 4 份样本，改写 100% 出现占位符 | 断言 |
| B2 | 虚构数值 0 例（含对抗样本） | 数值抽取比对 |
| B3 | 提示注入样本得分不受影响、不泄露 system prompt | 回归用例 |

### C. 检索与引用（3 条）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| C1 | 60 条 golden：Recall@5 ≥ 0.80，nDCG@10 ≥ 0.70 | 一键评测 |
| C2 | 人工抽检 50 条结论，引用确实支撑 ≥ 90% | 双人判定 |
| C3 | 点击引用定位正确率 100%（抽查 20 条） | E2E |

### D. 记忆（4 条）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| D1 | 跨会话召回探针 30 条通过率 ≥ 90% | 探针集 |
| D2 | 删除画像后 5 次会话 0 次出现 | 断言 |
| D3 | 反问句不写入偏好（10 条对抗，误写 0） | 用例 |
| D4 | A 的画像不出现在 B 的 prompt | prompt 断言 |

### E. 面试（5 条）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| E1 | 3 人设盲评可区分（5 人，识别率 ≥ 80%） | 人工 |
| E2 | 发散度 0/1/2 的材料引用率分别 ≥95% / ≥70% / ≤70% | 自动统计 |
| E3 | 答"不会"触发降维并记录盲区 ≥ 90% | 用例集 |
| E4 | 单场 10 轮重复问题率 < 10%，无死循环 | 相似度统计 |
| E5 | 不评外貌/籍贯/婚育，不泄露他人信息（20 条诱导 100% 拒绝） | 红队用例 |

### F. 报告与评分（4 条）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| F1 | 结束后 ≤ 10s 出报告，结构缺项 0 | 压测 |
| F2 | 每维附 ≥1 条原话证据 ≥ 90% | 抽检 |
| F3 | 同转录 3 次 ICC ≥ 0.70 或分差 ≤1 占比 ≥90% | 自动重跑 |
| F4 | 3 条改进均含"做什么/参考材料/耗时/完成标准" | 人工 5 分制 ≥ 4 |

### G. 评测与稳定（5 条）

| ID | 判据 | 方式 |
| :--- | :--- | :--- |
| G1 | 单命令产出 md + json，≤ 30 分钟，无手填数字 | 执行记录 |
| G2 | ≥5 组消融，含质量/延迟/成本 | 报告 |

## 8. 答辩与简历

### 8.1 90 秒开场（背下来）

> 我做的是一个给辽大同学用的求职 Agent。它不是聊天框——我用三个可验证的点来证明：
> 第一，**它不编数字**。简历里没有的压测数据，它会强制输出占位符而不是替你造，8 份对抗样本回归里虚构数值是 0 例。
> 第二，**它会降维追问**。四阶状态机，从设计动机问到量化证据；我说"这个没做过"，它会降级到基础概念并记进我的盲区，下一场面试开场直接问我。
> 第三，**每条建议都能点回原文**，页码级锚点，不是黑盒。
> 另外我做了两件容易被忽略的事：30 条越权用例全部拦截、删号 60 秒清空；以及一套 60 条的黄金评测集，每次改动都能看到指标是涨是跌。

## 9. 与 v2.0 的关系（面试被问"为什么不用 Kafka/Go"时）

> "我先按生产级思路设计过一版：Go 网关 + Kafka 削峰 + 三层记忆异步压缩。后来我算了一下业务量——全校日活最多几百人，峰值不到 10 QPS，Kafka 在这里唯一的作用是增加两个故障点。所以我把那版留作设计文档，落地版换成了单体 + Celery，把省下来的两周投到评测和护栏上。**这是我这个项目里最重要的一个技术决策。**"

这段话本身就是加分项：它证明你会做减法，而不是只会堆技术。
