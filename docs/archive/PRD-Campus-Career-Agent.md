## 1. 一句话定位

> **不是"会聊天的求职助手"，而是把学生私有材料变成"可追溯、可隔离、可度量"的求职能力闭环。**

三个关键词，缺一不可，也正好是答辩时的三张牌：

- **可追溯**：每一条建议、每一个分数，都能点回到"你的简历第 2 页 / 这份 JD 的第 3 条 / 这次面试的第 4 轮原话"。
- **可隔离**：每个用户的数据（简历、项目、实习材料、JD、对话、画像）物理与逻辑双隔离，可一键删除，且有越权测试证明。
- **可度量**：有 golden set、有消融、有一致性检验，能给出"同一模型下，harness 让引用正确率从 X 到 Y"这样的数字。

## 2. 背景与真实问题

辽大在校生（本科/硕士，计算机、软件、信管、电子等）在秋招中的真实卡点，按可解决性排序：

| # | 真实问题 | 现有解法为什么不够 | 我们能做什么 |
| :--- | :--- | :--- | :--- |
| P1 | 不知道自己的简历在目标岗位前"差什么"，改完仍同质化 | 通用大模型给出的建议泛化（"建议量化成果"），且无法对照具体 JD 与你的真实项目 | 简历 × JD 双向匹配 + 缺口定位 + **带引用**的改写，且不虚构数据 |
| P2 | 没有真实面试压力与反馈，练了也不知道哪句答得烂 | 同学互练缺专业度；付费模拟面试贵且一次性 | 多风格面试官 + 阶梯追问 + **逐句证据化**打分与复盘 |
| P3 | 求职信息过载，且存在培训贷、境外派遣、刷单灰产等虚假岗位 | 通用搜索无法判定"这个 JD 是不是坑" | 岗位风险规则库 + 语义研判 + 风险等级与依据 |
| P4 | 材料敏感（成绩、实习细节、家庭情况、薪资底线），不敢上传公有云 | 这是**合规硬约束**，也是本项目的护城河 | 全链路私有部署选项（可断网运行），数据可删除可审计 |
| P5 | 求职是长周期过程（3-12 个月），每次都从零开始讲背景 | 聊天工具没有跨会话的"你" | 三层记忆：会话态、事件态、画像态 |

## 3. 差异化论证：通用 Claude / Codex / ChatGPT 都能做，为什么还要做这个？

这是本项目最需要在答辩上讲清楚的一点，也是需求优先级的设计依据。

### 3.1 先把问题问对

通用模型是**能力供给方**，它解决"能不能写出这段话"。但求职场景真正的成本不在生成，而在**信任与责任**：

- 学生凭什么相信这个建议是对的？（需要**来源**）
- 学校凭什么允许学生的简历进入第三方云？（需要**边界**）
- 你自己怎么证明"这次的建议比上次好"？（需要**度量**）
- 面试官问"你项目的难点"，模型凭什么知道该往哪追问？（需要**领域策略与图谱**）

这四件事，通用工具**结构上不提供**，不是"做得差一点"，是"不做"。

### 3.2 模型是发动机，Harness 是底盘、刹车和仪表盘

这个类比建议直接用在答辩开场：

| 层 | 通用对话工具 | 本项目（Harness） |
| :--- | :--- | :--- |
| 动力（推理能力） | 强，且持续变强 | 直接复用（不跟它比能力） |
| 底盘（数据边界 / 多租户 / 记忆） | 无 | **自研，可测试** |
| 刹车（拒答、幻觉抑制、风险拦截、提示注入防御） | 弱、不可配置 | **规则 + 策略层，可评测拦截率** |
| 仪表盘（评测、一致性、成本、延迟） | 无 | **golden set + 消融 + 一键报告** |
| 领域资产 | 无 | 辽大 JD / 面经 / 专业-岗位映射 / 评分 rubric |

### 3.3 六条不可替代性（按可验证性排序，答辩就讲这六条）

1. **私有数据边界**：可离线运行（本地/校内网部署 Qwen 级模型 + 本地 embedding），核心链路断网可用。通用 SaaS 无法满足校园数据合规。
   *验证*：拔网线跑通"上传简历 → 匹配 → 面试 → 报告"。
2. **引用可追溯**：每条结论携带 `doc_id + page + 段落/bbox`，前端可点击定位原文。通用工具给文本，不给锚点。
   *验证*：引用正确率指标 ≥ 目标阈值（见 C 组验收）。
3. **策略显式化**：面试官人设、发散度、追问阶梯、评分维度是**状态机 + 配置**，不是提示词彩票；可 A/B、可消融，能证明"是策略起作用"。
   *验证*：不同发散度下追问内容分布可测量（见 F 组）。
4. **评分可校准**：同一份回答重复打分一致（ICC），与人工盲评相关（Spearman），并控制长度偏差、讨好偏差。
   *验证*：H 组一致性验收。
5. **领域数据资产**：辽大专业-岗位映射、校招时间线、真实面经题库、岗位风险规则库、5 类对抗样本（已有 `data/benchmark_resumes/`）。
6. **真实用户闭环**：10–30 位辽大同学灰度使用，记录任务完成率、建议采纳率、NPS。通用工具没有"为我们学校迭代"的版本。

### 3.4 诚实的边界（答辩时主动说，反而加分）

> "通用模型能覆盖我 60% 的功能。我不跟它比生成能力，我比的是**在校园求职场景下的可信度、可控性和可验证性**。如果只做一个聊天框，那确实是套壳；所以我把评测和隔离当成 P0 而不是加分项。"

### 3.5 如果只能保三件事

时间被压缩时，按此顺序保：**① 多用户隔离与可删除 → ② 带引用的私有 RAG → ③ 可复现的评测报告**。这三件是"套壳"与"工程系统"的分水岭。

## 4. 用户与场景

### 4.1 角色

| 角色 | 描述 | 权限 |
| :--- | :--- | :--- |
| 学生（主角色） | 辽大在校生，秋招/实习求职者 | 仅本人数据；上传、对话、面试、查看报告、管理画像、删除账号 |
| 就业指导老师（P2，可选） | 辅导员/就业中心 | 仅在被学生显式授权后，只读查看该生**脱敏后的报告摘要**，不可查看原始材料 |
| 系统管理员 | 运维 | 仅元数据与审计日志（不含材料内容），不可绕过学生删除 |

> P0 只做"学生"单角色，但数据模型与鉴权必须预留角色位，避免后期重构。

### 4.2 三个核心场景（写进演示脚本）

- **S1 改简历**：上传 2025 版简历 + 目标 JD → 得到匹配分（五维）+ 3 处最强缺口 + 每条改写的原文对照与出处 → 导出 2026 版。
- **S2 模拟面试**：选"大厂技术面试官 / 发散度 1" → 10 轮追问（沿项目事实→原理→边界→量化）→ 结束后报告：总分 72、技术深度弱、3 条可执行改进。
- **S3 项目复盘（对话模式）**：问"我这段实习最容易被追问什么" → 回答引用实习周报第 2 页 + 给出 5 个高概率追问 → 每个追问标注来源与建议回答骨架。

## 5. 目标与北极星指标

### 5.1 产品目标（6 周内）

1. 学生能在 15 分钟内完成"上传材料 → 匹配诊断 → 一次 10 轮模拟面试 → 拿到可执行报告"的完整闭环。
2. 任意两个用户之间，经由任何接口、任何检索路径，**零数据可见性**。
3. 一条命令产出一份自洽、可复现、含消融的评测报告。

### 5.2 指标

| 层级 | 指标 | 目标 |
| :--- | :--- | :--- |
| 北极星 | 周任务完成率（完成一次"改简历/面试/复盘"闭环的用户占比） | 灰度期 ≥ 60% |
| 质量 | 引用正确率 / 拒答准确率 | ≥ 90% / ≥ 90% |
| 质量 | 评分一致性（3 次重复打分 ICC） | ≥ 0.70 |
| 体验 | 首 token 延迟 p95 / 完整回答 p95 | ≤ 2s / ≤ 8s |
| 成本 | 单次完整面试（10 轮 + 报告）成本 | ≤ ¥0.6（给出预算表） |
| 安全 | 越权用例拦截率 | 100% |
| 安全 | 提示注入拦截率（含已有注入样本） | ≥ 90% |

## 6. 范围

### 6.1 做（P0）

F1 账号与多租户隔离 · F2 材料中心 · F3 私有知识库与多模态 RAG · F4 三层记忆 · F5 工具管理 · F6 对话模式 · F7 面试模式 · F8 复盘报告与评分 · F9 评测平台 · 最小可观测

### 6.2 不做（明确写进 PRD，避免范围爆炸）

- 不做投递代投、简历群发、企业端 ATS。
- 不做"美化/包装"简历（虚构经历的改写必须拒绝并提示），不做学历/经历造假辅助。
- 不做心理诊断与治疗建议（仅做轻量情绪支持并给出求助渠道）。
- 不做全网爬虫抓 JD（支持粘贴/上传截图，避免合规风险）。
- 不做多校区、多租户机构 SaaS（预留但不实现）。

### 6.3 现有工程盘点（基于代码阅读）

| 模块 | 现状 | 结论 |
| :--- | :--- | :--- |
| 文档解析 `services/parser.py` | PDF/DOCX/XLSX/CSV/MD/图片，结构感知切分，父子块 | **复用**，补"简历/JD 专用切分" |
| 检索 `services/retrieval.py` + `bm25.py` + `rerank.py` | 向量 / BM25 / hybrid，重排，邻接上下文扩展 | **复用**，补引用锚点与用户级过滤 |
| Agent 编排 `services/agent_workflow.py` | LangGraph 状态机 + 工具节点 | **改造**，接入工具注册表与策略 |
| 记忆 `services/memory_service.py` | Redis 实现 L1/L2/L3，带降级 | **改造**：加租户前缀、持久化、画像版本、删除 |
| 面试 `services/mock_interview.py` | 4 阶追问状态机（动机→原理→边界→量化） | **改造**：人设矩阵 × 发散度，固化进配置 |
| 匹配 `services/career_matcher.py` | 简历语义分块、五维雷达、STAR 改写 | **复用**，接引用与事实保真校验 |
| 风控 `services/job_fraud_detector.py` | 培训贷/境外/刷单等风险检测 | **复用**，规则库外置可维护 |
| 提示词 `services/prompt_service.py` | 全局单例模板，用户可改 | **必须改**：进程级全局状态会跨用户串味（隐私缺陷） |
| 评测 `benchmark/evaluator.py` + `report.md` | 有评测脚本与报告 | **重构**：报告数字自洽性与可复现性不足 |
| 前端 `pages/CareerCenter` | 已有单页原型 | **重构**：登录、材料库、双模式对话、报告页 |
| 鉴权 | **无**，默认 `default_student` / `default_user` | **新建（P0 第一优先）** |

> 已知缺陷（必须在验收前消除）：
> 1. `prompt_service` 的 `_active_templates` 是进程级全局字典，任意用户改提示词会影响所有用户 → 必须 per-user。
> 2. 记忆与画像仅存 Redis（TTL 7 天、无备份、无版本），无法满足"长期画像"与"可删除可审计"。
> 3. `backend/benchmark/report.md` 中三组数据互相矛盾（Baseline 任务完成率 73.3%，Hybrid 反而 33.3%），**答辩现场会被直接问穿**，必须用统一脚本重跑并锁版本。

## 7. 功能需求

### F1 账号与多租户隔离（P0）

- 登录：学号 + 密码（bcrypt/argon2 哈希），或校园邮箱验证码；JWT 短时效 + refresh。
- 会话：所有请求的 `user_id` **只能来自 token**，禁止 body/query 传 `user_id`。
- 隔离：数据库行级 `owner_id`、向量库按用户分区（collection 或强过滤）、对象存储按路径分区、Redis key 前缀 `u:{user_id}:`、提示词/工具配置 per-user 副本。
- 数据权利：导出（JSON/MD）、删除账号（级联清理，60s 内生效）、查看"谁在何时用过我的数据"（审计）。
- 验收见 A 组。

### F2 材料中心（P0）

四类材料，均支持多版本：

| 类型 | 上传 | 处理 | 备注 |
| :--- | :--- | :--- | :--- |
| 简历 | PDF/DOCX/MD/图片 | 结构解析 → 语义分段 → 版本对比 | 版本号 + 时间轴，可 diff |
| 项目材料 | 代码 README、架构图、设计文档、周报 | 解析 + 图片走 VLM 描述 | 与简历中的项目自动关联候选 |
| 实习材料 | 日报/需求文档/成果截图 | 解析 + 脱敏 | 默认高敏感级别 |
| JD/岗位 | 粘贴文本、截图、链接正文 | 结构化抽取：职责/硬性/加分/关键词/截止 | 支持"目标岗位"标记 |

- 异步解析（Celery）已有，补：进度、失败重试、解析质量自检（空页/乱码/低文本量告警）。
- 敏感分级：`normal / sensitive`；sensitive 材料默认不进检索召回，需显式勾选。

### F3 私有知识库与多模态 RAG（P0）

- 切分策略（按材料类型路由）：
  - 简历：**章节感知**（教育/技能/项目/实习/论文/奖项）→ 每个项目再切 1–3 子块，保留 `项目名/角色/时间/技术栈` 元数据。
  - JD：结构抽取 → 按"职责/要求/加分"成块，保留条目编号。
  - 项目/实习文档：父块 + 子块（复用现有 parent-child + `expand_context`）。
  - 图片/截图：VLM 生成描述 + OCR 文本，保留 `page + bbox` 以支持高亮定位。
- 检索：向量 + BM25 混合 → 重排 → 阈值截断 → 邻接扩展（复用现有实现），**强制注入 `owner_id` 过滤**。
- 引用：每个 chunk 携带 `doc_id, doc_type, version, page, bbox, section_path`；回答必须至少 1 条引用，不足则降级为"通用建议"标签。
- 支撑问题类型：跨材料推理（"这段实习和这个 JD 的第 3 条要求差在哪"）、时间线推理（"3 月到 6 月你做了什么"）、多模态（"这张架构图里的瓶颈在哪"）。

### F4 三层记忆（P0）

定义要精确到"存什么、何时写、何时读、何时忘"，否则只是一句口号。

| 层 | 名称 | 内容 | 存储 | 生命周期 | 读取时机 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| L1 | 工作记忆 | 当前会话最近 N 轮原文 + 任务槽位（模式、目标岗位、当前面试阶段、已问技能） | Redis（`u:{uid}:s:{sid}`） | 7 天 TTL | 每轮必读 |
| L2 | 情节记忆 | 结构化事件：一次面试/一次改简历（时间、岗位、人设、回合摘要、维度得分、识别出的弱项、结论） | 关系库 | 180 天 / 用户可删 | 面试前召回同岗位历史；对话中"上次说过" |
| L3 | 语义画像 | 技能标签（含置信度与来源）、目标岗位族、稳定弱项、表达偏好、历史分数曲线 | 关系库 + 版本表 | 长期，用户可编辑/删除 | 组装系统上下文；生成个性化建议 |

- **写入策略**：规则优先（槽位直接写）+ LLM 抽取（弱项/偏好）+ **用户确认**（画像页可见可改）。禁止把疑问句、反问句误写为偏好（现有实现已有前置拦截，保留并测试）。
- **冲突处理**：新值覆盖旧值但保留 `source_event_id + 时间`；置信度衰减（90 天未复现的弱项降权）。
- **遗忘**：L1 TTL；L2 按时间/手动；L3 手动删除即失效；删账号级联。
- **隐私**：写入前 PII 检测（身份证/手机号/住址/银行卡）→ 脱敏或不写；记忆内容不进入跨用户任何路径。
- **可解释**：面试开场主动说"我记得你上次在 Redis 缓存击穿上失分，这次会再考"——**这是演示时最有说服力的一秒**。

### F5 工具管理（P1）

- 工具注册表（JSON Schema）：`name / description / input_schema / side_effect(read|write|external) / timeout / cost / enabled / scope`。
- 权限：只读检索类默认放行；外发类（联网查岗位）需用户确认；写类（改简历）必须二次确认 + 可回滚。
- 审计：`tool_calls` 表（call_id、user、session、tool、args 摘要、结果哈希、耗时、token、错误）。
- 前端："本次回答用到的工具"折叠面板（复用现有 recall 面板样式），展示输入/耗时/来源数。
- 失败处理：重试 1 次 → 降级 → 明确告知用户"某工具不可用，以下结论仅基于材料"。
- 工具清单（P0）：`search_resume` / `search_jd` / `search_project` / `search_internship` / `skill_graph_query` / `job_risk_check` / `resume_diff` / `score_answer`。

### F6 对话模式（P0）

定位：**求职咨询与材料复盘**，不是通用聊天。

- 能力：项目复盘追问、简历与 JD 差距分析、STAR 话术打磨（给 diff 而非整段重写）、岗位风险研判、求职节奏与心态支持。
- 硬规则：
  1. 结论必须带来源徽章（材料名 + 位置）；无来源则显式标注"通用建议，未引用你的材料"。
  2. 不虚构学生经历；需要数据时输出占位符 `[请补充真实指标]`（已有事实保真规则，保留）。
  3. 不确定即说不知道，并给出"可以怎么查/怎么补"。
- 参考技能图谱做追问引导（"你写了 Redis，接下来可能会被问击穿/雪崩/穿透的区别"）。

### F7 面试模式（P0）

- **人设矩阵**（配置化，非提示词）：

| 人设 ID | 风格 | 严格度 | 技术深度 | 默认发散度 | 典型追问 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `bigtech_tech` | 大厂技术面试官 | 5 | 5 | 0 | 你这里为什么不用 X？压测数据怎么来的？ |
| `hr_behavior` | HR 行为面 | 3 | 2 | 1 | 讲一次你和同事冲突；为什么选我们 |
| `startup_cto` | 创业公司 CTO | 4 | 3 | 2 | 预算砍一半你怎么做？这个方案上线会炸在哪 |
| `alumni_mentor` | 温柔校友学长 | 2 | 2 | 1 | 别急，我们一步步拆；你觉得问题出在哪 |

- **发散度（0/1/2）可配置**：

| 档位 | 允许的提问范围 | 必须满足 | 观测指标 |
| :--- | :--- | :--- | :--- |
| 0 | 仅材料内事实 + 原理 + 工程边界 | 每轮引用材料锚点 | 材料引用率 100% |
| 1 | 可延伸到相邻技术、行业常识 | 延伸后必须回到材料 | 材料引用率 ≥ 70% |
| 2 | 可进入情境假设、职业选择、行业趋势 | 必须标注"延伸题"，且总占比 ≤ 30% | 延伸题占比 20–30% |

- **追问阶梯**（复用现有 4 阶状态机，补自适应）：动机/选型 → 核心机制 → 工程边界 → 量化证据 → 收敛复盘；学生答"不会"时 `PIVOT_FALLBACK` 降维引导并记录盲区。
- 每轮可选即时反馈（默认开，可关）；每 3–5 轮允许一次 hint（计入评分扣分项，可配置）。
- 约束：不评价外貌/籍贯/性别/婚育；不透露其他用户信息；不输出"标准答案"（避免降低考察效度）；单场 8–15 轮，重复问题率 < 10%。

### F8 复盘报告与评分（P0）

- 触发：面试结束（用户点"结束"或达到轮次上限）→ ≤ 10s 出报告（流式拼装）。
- 内容：
  1. 总分（100）+ 五维雷达（事实一致性 / 技术深度 / 结构化表达 / 量化证据 / 沟通抗压），每维含**锚点描述 + 该维得分 + 证据引用（学生原话）**。
  2. 逐题卡：问题 / 你的回答摘要 / 得分 / 面试官评语 / 更好的回答骨架（不给整段范文）。
  3. **3 条本周可执行改进**：做什么 + 参考哪份材料 + 预计耗时 + 可验证的完成标准。
  4. 与上一次同岗位面试对比（分数趋势 + 弱项是否收敛）。
  5. 下一步建议（练什么题型、补什么知识点，链接到技能图谱节点）。
- 评分纪律：temperature ≤ 0.3；rubric 锚点固定；同一转录 3 次打分 ICC ≥ 0.70；与 2 人盲评 Spearman ≥ 0.6；控制长度偏差（不因答得长而高分）。
- 导出：Markdown / PDF；报告本身也带引用（可回溯到面试逐轮记录）。

### F9 评测平台（P0，项目的"仪表盘"）

- 一键：`make eval`（或 `python -m benchmark.run_all`）→ 产出 `reports/eval-<date>.md` + 原始 JSON。
- 数据集（资产，持续扩充）：
  - 简历/JD/项目材料样本（已有 `data/benchmark_resumes/` 5 类对抗样本：正样本、弱样本、夸大、注入、跨域错配）。
  - RAG golden：60–100 条 query，标注 `doc, page, chunk` ground truth。
  - 记忆探针：30 条（跨会话偏好生效、冲突覆盖、删除生效、跨用户不可见）。
  - 越权用例：≥ 30 条（资源 × 用户对）。
  - 面试场景：20 个（岗位 × 难度 × 人设 × 发散度）。
- 指标：
  - RAG：Recall@5、nDCG@10、MRR、引用正确率、拒答准确率、延迟、token 成本。
  - Agent/面试：任务完成率、追问相关性（LLM-judge + 人工 30 条校准一致率 ≥ 80%）、重复率、阶段推进合规率、评分 ICC、报告建议可执行性（人工 5 分制 ≥ 4）。
  - 记忆/安全：探针通过率 ≥ 90%、越权拦截 100%、注入拦截 ≥ 90%、PII 泄漏 0。
- 消融（≥ 5 组）：`L0 直接 LLM` → `+RAG(纯向量)` → `+hybrid+rerank` → `+三层记忆` → `+工具与护栏` → `full`。
- 可复现：固定模型版本/温度/seed、prompt 版本号、数据集版本号、报告与 JSON 一一对应；报告内所有数字由脚本写入，禁止手填。

### F10 最小可观测（P1）

- 全链路 `trace_id`（请求 → Agent 节点 → 工具 → LLM 调用）。
- 每次会话记录：token、成本、延迟、检索命中、工具调用数、错误码。
- 一个 `/admin/health` 与一个成本看板（本周花费/人均）。

## 10. 非功能需求

| 类别 | 要求 |
| :--- | :--- |
| 性能 | 对话首 token p95 ≤ 2s；完整回答 p95 ≤ 8s；50 页 PDF 解析 ≤ 60s（异步）；20 并发不降级 |

| 安全 | JWT 短时效；密码哈希；上传类型白名单 + 大小限制；注入防护用 XML/JSON 隔离输入（已有注入样本可回归） |

| 合规 | 明示 AI 生成内容；不提供虚假经历包装；不收集身份证/家庭信息（如用户上传，自动脱敏并提示） |
| 成本 | 单次面试 ≤ ¥0.6；日预算告警；缓存复用（embedding/检索结果） |
| 可部署 | docker compose 一键起；离线模式（本地模型）可跑通核心链路 |
| 可维护 | 版本化：prompt / rubric / 数据集 / 模型 都有版本号并写入报告 |

## 11. 验收准则（Acceptance Criteria）

**使用方式**：每条有唯一 ID，P0 必须全部通过才能演示/上线；P1 为加分项。执行结果汇总到 `docs/acceptance-report.md`，附命令与输出。**判据必须是数字或可自动断言的事实，不接受"体验良好"。**

### A. 多用户隔离与隐私（P0，最高优先）

| ID | 验收点 | 通过判据 | 验证方式 |
| :--- | :--- | :--- | :--- |
| A1 | 鉴权强制 | 无 token / 过期 token 访问任一业务接口 100% 返回 401 | pytest 参数化覆盖全部路由 |
| A2 | 身份不可伪造 | 代码中不存在 `default_user` / `default_student` 等隐式用户；body 内 `user_id` 被忽略 | 静态断言（grep + 单测） |
| A3 | 跨用户读隔离 | ≥30 条用例（material/chunk/session/turn/report/profile/memory × 用户对）全部 403/404 | 自动化越权测试套件 |
| A4 | 检索隔离 | 两用户上传同名同内容文档，各自检索仅返回本人 chunk，交叉污染 0 次 | 双用户端到端脚本 |
| A5 | 记忆隔离 | 用户 A 的 L3 画像不出现在 B 的任何 prompt 中 | 注入探针 + prompt 断言 |
| A6 | 提示词隔离 | A 修改面试官提示词后，B 的提示词与输出不受影响 | 双账号回归用例 |
| A7 | 级联删除 | 删除账号后 60s 内：DB / 对象存储 / 向量库 / Redis / 报告文件 全部 0 残留（审计日志除外） | 删除后全库扫描脚本 |
| A8 | PII 脱敏 | 上传含身份证/手机号的简历，日志与记忆写入中 0 明文 | 正则扫描日志与 Redis 快照 |
| A9 | 数据导出 | 导出包包含该用户全部材料、会话、报告，且不含他人数据 | 导出内容断言 |

## 13. 风险与应对

| 风险 | 影响 | 应对 |
| :--- | :--- | :--- |
| 数据集太小，指标不可信 | 答辩被质疑"过拟合自己的 8 份样本" | 明确规模与局限；用公开真实简历扩充到 ≥30 份；报告写样本量 |
| 评分主观 | 分数不可信 | 只做**相对比较**（自己 vs 自己）、锚点固定、ICC 报告、人工校准 |
| 现有评测报告数字矛盾 | 现场被问穿 | 用统一脚本重跑，删除旧报告，锁 commit |
| 多租户改造量大 | 延期 | 用"仓储层强制 owner 过滤"一刀切，禁止路由层裸查询 |
| LLM 成本/不稳定 | 演示翻车 | 熔断 + 缓存 + 固定温度 + 录屏兜底 |
| 隐私合规 | 校园推广受阻 | 离线模式 + 明示 + 可删除 + 不收集身份证 |

## 14. 答辩话术（预演）

**Q1：这不就是套壳大模型吗？**
> 通用模型给的是文本，我给的是**能核对、能删除、能度量**的东西。三句话：数据不出校（可断网演示）；每句话可点回你的材料；有 golden set 和消融，同一模型下引用正确率从 X 到 Y、评分一致性 ICC 0.xx。这三件事它不是做得差，是不做。

**Q2：ChatGPT 也能传简历、也能模拟面试。**
> 能传，但不给你页码级引用，不给你跨会话的稳定画像，不给你可配置的发散度和追问阶梯，更不能证明"这次比上次强在哪"。而且学校不会允许学生简历进公有云——这是合规问题，不是体验问题。

**Q3：你的技术难点在哪？**
> 四个：① 三层记忆的写入策略、冲突覆盖、可删除与不误写；② 多租户隔离的可测试性（30 条越权用例全绿才算完）；③ 简历/JD 的结构保真切分与引用锚点；④ 评分 rubric 的一致性与偏差控制。都是"看起来简单、做起来要证据"的活。

**Q4：如果给你更多时间？**
> 把数据集从 60 条扩到 500 条并引入真实投递回收率做长期效果验证；把本地小模型蒸馏成校内可部署版本；接入就业中心的岗位库做冷启动。
